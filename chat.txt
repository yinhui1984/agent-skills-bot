def agent_loop(user_input):
    # 1. 匹配 skill
    skill = match_skill(user_input)
    
    # 2. 构建 prompt
    system_prompt = build_prompt(skill)
    
    # 3. 初始化消息
    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_input}
    ]
    
    # 4. 循环直到完成
    while True:
        response = call_deepseek(messages, tools)
        
        if no tool_calls:
            return response.content  # 完成
        
        # 5. 执行工具
        for tool_call in response.tool_calls:
            result = execute_tool(tool_call)
            messages.append(tool_result_message)

关键设计决策
Q1: 内置工具 vs 自定义工具的边界？
内置工具（通用的）：

bash_tool - 执行任何命令
python_tool - 运行 Python 脚本
nodejs_tool - 运行 Node.js 脚本
create_file_tool - 创建文件
view_file_tool - 查看文件
自定义工具（特定领域的）：

analyze_storage_layout - Web3 专用
compile_solidity - Solidity 专用
run_foundry_command - Foundry 专用
Q2: 为什么不直接用 bash_tool 调用所有命令？
可以！但专用工具有优势：

python
# 方案 A: 纯 bash
tool_call = {
    "name": "bash_tool",
    "arguments": {
        "command": "cd /path && python3 eip1967_inspector.py --address 0x... --rpc https://..."
    }
}

# 方案 B: 专用工具
tool_call = {
    "name": "analyze_storage_layout",
    "arguments": {
        "contract_address": "0x...",
        "rpc_url": "https://..."
    }
}
专用工具的好处：

类型安全：参数有明确的类型定义
更好的错误处理：可以做参数验证
更清晰的意图：DeepSeek 更容易理解该用哪个工具
可以包装复杂逻辑：比如自动找到 inspector 脚本路径

def load_skill_tools(skill):
    """根据 skill 的 allowed-tools 字段解析工具"""
    allowed = skill.frontmatter.get("allowed-tools", "")
    
    if not allowed:
        # 没有声明，使用全套基础工具
        return BASE_TOOLS
    
    # 解析 allowed-tools
    # "Bash(git:*) Bash(jq:*) Read" → ["bash_tool", "view_file"]
    tools = parse_allowed_tools_spec(allowed)
    return tools

问题的本质
你问的是：我们给 DeepSeek 提供的 tools 应该在什么抽象层次？

三种设计方案对比
方案 A: 裸 bash_tool（最简单）⭐ 推荐 MVP
Tool 定义:

json
{
  "type": "function",
  "function": {
    "name": "bash_tool",
    "description": "Execute any bash command on the system. You have access to all standard Unix commands like cat, echo, ls, grep, python3, node, git, foundry tools, etc.",
    "parameters": {
      "type": "object",
      "properties": {
        "command": {
          "type": "string",
          "description": "The complete bash command to execute"
        },
        "description": {
          "type": "string", 
          "description": "Why you're running this command"
        }
      },
      "required": ["command"]
    }
  }
}
DeepSeek 看到的就是一个万能工具

它自己知道:

✅ cat file.txt - 读文件
✅ echo "content" > file.txt - 写文件
✅ which anvil - 检查工具是否存在
✅ python3 script.py - 运行 Python
✅ forge test - 运行 Foundry
为什么 DeepSeek 知道用 which？

因为它的训练数据中包含大量的：

Shell 脚本
GitHub 代码
Stack Overflow 问答
所以它"学会"了：

读取文件 → cat
创建文件 → echo 或 tee 或重定向

极简实现，只需实现一个 tool

无需预测用户需要什么工具
缺点:

无法做参数验证
错误处理粗糙
安全性依赖黑名单

go
// internal/tool/bash.go

func ExecuteBash(args map[string]interface{}) (string, error) {
    command := args["command"].(string)
    
    // 安全检查
    if isBlacklisted(command) {
        return "", fmt.Errorf("命令被禁止: %s", command)
    }
    
    // 执行
    cmd := exec.Command("bash", "-c", command)
    output, err := cmd.CombinedOutput()
    
    return string(output), err
}

// 工具定义
var BashToolDefinition = Tool{
    Type: "function",
    Function: ToolFunction{
        Name: "bash_tool",
        Description: `Execute bash commands on the system. 
You have access to all standard Unix commands (cat, echo, grep, etc.) 
and any installed tools (git, python3, node, foundry, etc.).

Best practices:
- Check if tools exist before using them: which <tool>
- Use standard Unix commands for file operations
- Provide clear descriptions of what you're doing`,
        Parameters: map[string]interface{}{
            "type": "object",
            "properties": map[string]interface{}{
                "command": map[string]interface{}{
                    "type": "string",
                    "description": "The bash command to execute",
                },
                "description": map[string]interface{}{
                    "type": "string",
                    "description": "Human-readable explanation of what this command does",
                },
            },
            "required": []string{"command"},
        },
    },
}

```
## 如果要实现文件操作工具（可选）

### 为什么要专门的文件工具？

**场景：读取一个 10MB 的文件**

**方案 A (bash_tool)**:
```
tool_call: bash_tool("cat large_file.sol")
→ 返回整个文件内容（可能超出 context window）
方案 B (read_file):

go
func ReadFile(args map[string]interface{}) (string, error) {
    path := args["path"].(string)
    startLine := args["start_line"].(int)  // 可选
    endLine := args["end_line"].(int)      // 可选
    
    // 可以做智能截断
    if fileSize > 100KB {
        return "文件太大，请指定行范围", nil
    }
    
    // 读取指定范围
    return readLines(path, startLine, endLine), nil
}
优势:

可以限制返回大小
可以支持行范围
更好的错误处理
